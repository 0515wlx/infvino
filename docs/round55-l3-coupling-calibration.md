# R55：L3 的 occupancy ↔ miss 耦合标定（决定建模形态的实测）

> 动机（用户）：L3 成本函数要「完整建模」，但**可加性要尽量保留**。「occupancy 和 miss
> 都对性能有影响，而且二者耦合」——所以在决定用哪种模型（可加主问题 + 价格，还是别的）之前，
> **先用实测把二者的耦合结构标定清楚**。
>
> 本文只做**标定与判读**，不预设模型。判读结论见 §5，据此决定的建模形态见 §6。

---

## 0. 结论先给（TL;DR）

在锁频（min=max=RP0=1300）的 Iris Xe（80 EU，标称 L3 = 3.75 MiB）上，用一个**把「驻留足迹 R」
与「并发度 C」解耦**的微基准（`kernel_bench --op l3couple`）得到：

1. **容量/ miss 由单一变量 `R = C · perWG` 控制**（C=并发线程数，perWG=每个 WG 的在飞足迹字节）。
   固定 `R`、改变 `(C, perWG)` 的拆分方式，有效吞吐几乎不变（归一化后 0.90–1.00，见 §3.3）。
   → R47 的 `occupancyPressure = min(threads,8192) × perWG` **正是这个 R**，结构正确。
2. **并发度 C 决定可达上限 `BWmax(C)`**（MLP / 在飞请求数），与容量**乘性可分离**：
   `BW(C, R) ≈ BWmax(C) · g(R)`。C 从 256→1024 WI 近似翻倍，约 1024–2048 WI 饱和。
   → 这部分是**逐节点、可加**的。
3. **有效容量断崖 ≈ 2 MB**（私有 tile 模式；平台延伸到 ~2 MB，半坡 ~6 MB，DRAM 平台 ≥16 MB），
   而非标称 3.75 MB。单条协作大流（copy）的断崖在 ~2.5 MB。二者差在**访问模式**（私有窗口 vs
   协作流），需在模型里选择与 kernel 形态匹配的锚点。
4. 因此**「occupancy 与 miss 的耦合」实际是「局部占用因子 × 全局容量因子」的乘积**：
   - 容量因子 `g(R)`：全局、顺序相关（A 的 R 逐出 B 的数据）→ 保留为非可加项 / 定价；
   - 并发因子 `BWmax(C)`：逐节点、可加 → 可以干净地进可加主问题。
   这给「方案 A：可加主问题 + 精确全局模拟器」提供了可直接落地的**结构 + 实测锚点**。
5. **跨算子污染的直接证据（双租户，`--op l3pollute`）**：一个 1 MB、被反复重用（MRU）的共享
   热点，在 aggressor 流式足迹 ≤ 8 MB 时**完全命中**（1.00×），到 **12.6 MB 才被逐出**（2.24×），
   33.5 MB 贴 DRAM（5.78×）。阈值 **~8–12 MB ≈ 2–3× 标称 L3**，**远大于**单租户的有效容量
   ~2 MB（§3.6）。→ 跨算子逐出是**近期重用（LRU/recency）加权**的，**不能**用「Σ 足迹 > C」的
   简单阈值：被频繁重用的张量（MRU）会抵抗流式占用，直到后者自己也需要驻留。这直接影响 §5/§6。

## 1. 实验设计：把 R 与 C 解耦

难点：驻留足迹天然是 `R = C × perWG` 的乘积，直接扫网格会把二者搅在一起（R47 的 `footprint`
基准即如此）。新内核 `kernels/micro.cl::l3_probe` 让每个 work-item 反复触碰一块**私有、互不
重叠**的窗口（`fp` 条 cache line，64 B/条），`passes` 遍：

```
驻留足迹 R = C · perWG · ...            （C = gws 线程，perWG = fp 条 = fp·64 B）
触碰次数 T = C · fp · passes
```

于是：
- **固定 C、变 fp**：改 R → 看容量/miss 效应；
- **固定 R = C·fp·64、变 (C, fp)**：C 与 fp 反向变 → 看纯并发/MLP 效应；
- **passes=1**：纯流式，无复用（R 不决定命中，只决定在飞量）；**passes=64**：高复用，
  R 决定逐遍命中还是 Miss。

指标：**有效行吞吐** `T·64B / time`（每次触碰计 64 B 行；命中 L3 远高于 Miss 到 DRAM）。

复现命令（锁频）：

```bash
scripts/gpu_clocks.sh lock
./build-ct/kernel_bench --op l3couple --passes 1  --wi 256,512,1024,2048,4096,8192 --fp 1,2,4,8,16,32,64
./build-ct/kernel_bench --op l3couple --passes 64 --wi 256,512,1024,2048,4096,8192 --fp 1,2,4,8,16,32,64
./build-ct/kernel_bench --op l3couple --passes 64 --wi 4096,8192 --fp 1,2,3,4,6,8,12,16,24,32,48,64,96,128
scripts/gpu_clocks.sh unlock
```

## 3. 判读

### 3.1 F1 —— 容量由 `R = C·perWG` 单一控制
`passes=1` 下，不同 C 的峰值**都**落在 R≈1 MB；`passes=64` 下，R≈1–2 MB 是平台。改变
`(C, perWG)` 拆分方式不改变断崖位置。→ **R 是容量变量的正确聚合**。

### 3.2 F2 —— 并发 C 决定可达上限（乘性因子）
固定 R 时，吞吐仍随 C 上升（低并发 MLP 不足）。归一化后 `BW/BWmax(C)` 对 R 塌缩成**同一条
曲线**（§3.3 表），故 `BW(C,R) ≈ BWmax(C)·g(R)`——**乘性可分离**，不是强耦合。

### 3.3 F3 —— 归一化塌缩（固定 R，变 C）

| R (KB) | C=256 | C=512 | C=1024 | C=2048 | C=4096 | C=8192 |
|---:|---:|---:|---:|---:|---:|---:|
| 256  | 0.99 | 0.98 | 0.96 | 0.97 | 0.90 | — |
| 512  | 1.00 | 0.99 | 0.99 | 0.96 | 1.00 | 0.92 |
| 1024 | 1.00 | 1.00 | 1.00 | 0.99 | 0.99 | 0.96 |
| 2048 | — | 0.87 | 0.85 | 1.00 | 0.91 | 1.00 |
| 4096 | — | — | 0.55 | 0.58 | 0.62 | 0.70 |

同一 R 下跨 C 的归一值一致（±10%）→ 支持乘性可分离。

### 3.4 F4 —— 有效容量随**访问模式**变化
私有并发窗口（本基准）有效容量 ≈ 2 MB；单条协作大流（copy）断崖 ≈ 2.5 MB；标称 L3 = 3.75 MB。
→ 模型里「有效容量」不是一个物理常数，而是与 kernel 的**并发/分块形态**有关的量；对
conv/gemm 这类**每 WG 私有 tile** 的形态，应取 **~2 MB** 一档。

### 3.5 F5 —— 跨算子污染（双租户）**直接测量**

单节点 R 扫描只能推出「驻留→miss」的机制；「A 的占用逐出 B 的输入」需要**两租户**实验直接看。
新增内核 `micro.cl::l3_hot_read` + `--op l3pollute`：先入队一个 **aggressor 流**（私有足迹
`R_A`，一次流式、无复用），紧接着**协作重读一个共享热点**（1 MB，MRU）；`timeMs` 只profile热读
event（aggressor 在同一个 in-order 队列里、不计时），于是**热读的吞吐**直接反映热点有没有被逐出。
参考点取平台区中段（R_A=1 MB，确定无污染；并丢弃一次以避开首测冷启动）。

**1 MB 热点（hot_gws=8192，锁频）**：

|---:|---:|---:|---:|---|
| 1.05 (ref) | 0.0098 | 106.5 | 1.00 | 全命中 |
| 2.10 | 0.0098 | 106.5 | 1.00 | 全命中 |

对照（512 KB 热点）：≤8.4 MB 全命中，16.8 MB 掉到 28.6–35.8 GB/s（1.5–1.9×）；
（128 KB 热点）：~4–8 MB 即开始掉（1.2–1.6×）。三档一致指向**阈值 ~8–12 MB**。

**判读**：
- **跨算子 L3 污染确实存在**（热点在 aggressor 超过阈值后变慢 2–6×）——用户假设成立。
- 阈值 **~8–12 MB ≈ 2–3× 标称 L3**，**远大于**单租户私有窗口的有效容量 ~2 MB（§3.4）。
  原因：热点被反复重用（MRU），无复用的流式 aggressor 在 LRU 下**先被逐出**；要冲掉 MRU
  热点，aggressor 必须大到自身也需驻留（超过容量）。
- **结论**：逐出是**近期重用加权**的 → 必须用 **LRU / stack-distance** 这类考虑复用次数的模型，
  **不能**用「Σ 足迹 > 常数」的简单阈值（后者会把频繁重用的张量误判为必被逐出）。

### 3.6 诚实边界
- 行粒度指标（touch=64B，实际只用 4B）与 copy 口径不可直接换算；本节只用**归一化形状**与**相对比值**。
- `l3pollute` 的 aggressor 是**私有窗口流**（每 WG 独立、line 步长），真实 kernel 读写更规则；
  阈值应在真实 conv/gemm tile 形态上复标。
- 无 OA 计数器，命中/逐出由**时间**推断；本实验用「同一参考、仅改 R_A」的一阶差分规避绝对值标定。

## 5. 判读结论：该用什么模型形态

「occupancy 与 miss 耦合」在本机上的真实形态是：

```
time_i  = bytes_i / ( BWmax(C_i) · g(R_i) )          # 逐节点：C_i, R_i 都是该节点自己的量
spill   = κ · Σ_t B_t · 1[ reuseDist_t + Σ_{j∈W(t)} R_j > C_eff ]   # 全局：跨节点逐出
Cost    = Σ_i (compute_i + time_i) + spill
```

- **`BWmax(C_i)` 与 `g(R_i)` 都是逐节点、可加**的（R_i 只依赖该候选自己的 tiling/grid）。
- **只有 `spill`（窗口逐出）是全局、顺序相关、非可加**的。
- 因此**可加主问题**可以装下「计算 + 内存 roofline（含并发 + 容量因子）」，把**仅剩的
  跨算子逐出**交给**精确全局模拟器 / 定价**（Scheme A）。
- ⚠️ 上式里 `reuseDist_t + Σ R_j > C_eff` 只是**一阶边界**写法（便于定价/边界张量分解）；
  双租户实验（§3.5）表明逐出是**近期重用加权**的，故 `spill` 的**精确求值必须用 LRU 模拟**
  （R47 现状），`C_eff` 取 `g(R)` 曲线而不是硬阈值。

这与 R49 §10 的负结果不矛盾：那里失败的根因是把 `occupancyPressure`（= R，足迹)**当成了
miss 字节**。本标定表明 R 的正确用法是**压缩有效容量并给容量曲线定价**，而非直接线性计入。

## 6. 建模建议（供决策）

1. **把 `copyBwGbps` 升级为二维 `BW(C, R)`**：`BW = BW_mlp(C) · g(R)`。
   - `BW_mlp(C)`：由 `l3couple` 的 `BWmax(C)`（或 `occwgs`）标定，饱和 ~1024–2048 WI；
   - `g(R)`：由 §2.3 平滑成单调曲线，`C_eff ≈ 2 MB`。
   - 这一步**保持可加**（逐节点）。
2. **全局 eviction 保留精确 LRU 模拟**（§3.5 支持其「近期重用加权」语义），容量改用 §2.3 的
   `g(R)` 曲线；**不要**把它退化成 `Σ R > C` 的硬阈值。
3. **可加主问题**（mincut / 坐标下降）里只装 §6.1 的逐节点成本 + **有限差分/边界张量价格**
   `ρ_i`（方案 A）；全局模拟只做**标定与最终评分**。
4. **补标定**（可选）：per-family 的 `perWG` 权重（用真实 conv/gemm 的 tile 形态做 2D 扫描）；
   把 `l3pollute` 的阈值在真实 tile 形态上复标。

## 7. 实现：方案 A（可加主问题 + 有限差分定价）

按 §6 落地「**可加主问题 + 非可加精确求值/定价**」，让非线性只通过**价格重标定**注入。

### 7.1 新模块 `L3Model`（可离线单测）

`include/infvino/L3Model.hpp` / `src/L3Model.cpp`：

```
struct L3Access { op; occ_bytes; reads; writes; }      // 一个算子在 L3 模拟里的视图
struct L3Result { spill_bytes; spill_ms; node_price_ms; }
L3Result evaluateL3(nodes, cfg);                       // 全局 LRU 模拟 + 逐节点价
```

- `evaluateL3` 按拓扑序跑一遍 LRU 模拟（占用压缩容量 → 逐出 LRU 头 → 读记 miss/写），
  与 R47 的 `globalRetune` 内联实现同源；`predictNet` 已改为调用它（**行为不变**，单一真相源）。
- `compute_prices=true` 时用**有限差分**给出 `ρ_i`：
  `node_price_ms[i] = (spill(occ_i) − spill(occ_i→0)) · κ`（单位 ms，≥0）。

### 7.2 R55 校准函数（`Tuning.hpp/cpp`）

- `occupancyThreads(e,s)`：导出与 `occupancyPressure` **同源**的并发线程数 C（重构了
  `occupancyStats` 单一真相源，`occupancyPressure = C · perWG` 行为不变）。
- `l3MlpFactor(C)`：并发/MLP 因子（~1024 线程饱和），给 `copyBwGbps` 补上**并发维**。
- `l3CapacityFactor(R)`：容量因子 g(R)（平台 ~2MB），把 `l3couple` 实测曲线编码进来。
- `effectiveBwGbps(bytes, threads) = copyBwGbps(bytes) · l3MlpFactor(threads)`（逐节点、可加）。

### 7.3 mincut 的定价主问题（`resolveLayoutMinCut`）

`INFVINO_LAYOUT_L3=1` 时，节点代价表加一项 `ρ · occupancyPressure(candidate)`（ms/占用字节）。价格的两种标定：

```
collective (默认): ρ = S_occ / ΣR     S_occ = spill(occ) − spill(occ≡0)   # 集体：总可省溢出按占用摊平
pernode:           ρ_i = ρ_i^{fd}     逐节点有限差分（局部，易高估单节点可实现削减）
```
`INFVINO_L3_PRICE=pernode` 切换；`INFVINO_L3_PRICE_SCALE=<x>` 缩放（消融/标定）。
另加**离线评分拒绝门**（`INFVINO_NO_LAYOUT_L3_GATE=1` 关）：mincut 提案的
`layoutModelScore = Σ kernel ms + Σ reorder + spill_ms` 若比 baseline 差 >0.5% 就回退。

- 量纲是 ms（修正 R49 §10 把占用字节当 miss 字节的负结果）。
- `ρ` 由**当前选择**的全局模拟重标定（`buildL3Access()` 唯一入口）。
- 默认关；`INFVINO_LAYOUT_REPORT=1` 打印 `R55 price(mode): spill=… S_occ=… rho_max=…`。

### 7.4 离线测试（零 GPU）

- 新增 `tests/test_l3_model.cpp`：生产者→消费者命中=0 miss；冷输入记 miss；占用逐出→后续 miss；
  **唯一元凶夺得全部价格**、无害占用价格=0、价格随占用单调、确定性、关闭定价无价格向量。
- `tests/test_rulers.cpp` 增补：`l3MlpFactor` 饱和/单调、`l3CapacityFactor` 平台/单调、
  `effectiveBwGbps = copy×mlp`、`occupancyThreads` 与 pressure 同源。
- `cmake --build build-ct --target check` → **6/6 PASS**。

### 7.5 完整一轮 A/B（锁频、交错、交替臂序、6 rep、`--iters 15`）

三条臂：`base`（默认 mincut） / `collective`（L3 集体价 + 拒绝门） / `pernode`（L3 逐节点价 + 拒绝门）。

| 模型 | arm | busy median | Δ vs base | fsv16 | reorder 次 |
|---|---|---:|---:|---:|---:|
| mb | base | 1.389 | — | 23 | 9 |
| mb | collective | 1.394 | +0.36% | 23 | 9 |
| mb | pernode | 1.403 | **+1.04%** | 23 | 9 |
| y11 | base | 11.277 | — | 9 | 12 |
| y11 | collective | 11.334 | +0.51% | 9 | 9 |
| y11 | pernode | 11.482 | **+1.81%** | 7 | 14 |
| y8 | base | 10.543 | — | 0 | 5 |
| y8 | collective | 10.532 | **−0.10%** | 0 | 5 |
| y8 | pernode | 10.622 | **+0.75%** | 0 | 6 |

**结论（负结果 + 中性）**：
1. **pernode 一致回归**：y11 +1.81%（fsv16 9→7、reorder 12→14，多付 reorder）；y8 +0.75%（多 1 次 reorder）；
   mb +1.04%。有限差分把「单节点占用归零」的削减全额记在它头上，**高估**可实现的溢出削减。
2. **collective 中性**（−0.10%~+0.51%，噪声内）：`S_occ/ΣR` 被摊得很小（y11 ρ_max 7e-10 ms/B），
   对 mincut 影响接近零 → 安全但**无收益**。
3. **拒绝门失效**：pernode 提案的 `layoutModelScore` 反而**更低**（模型自认为更好），门不会拦——
   根因是**模型对溢出削减过于乐观**，模型自评分无法防这类回归。
4. **mb 的 spill 与占用无关**（§3.5 的诊断：`spill|occ=0 == spill`）→ 价格恒 0，这是「张量逐出项是
   赋值不变量」（R47 §7）的再次确认。

### 7.6 诚实边界

1. **锚点**：`eff_cap_anchor` 默认 1MB（保持 R47 `predictNet` 不变）；R55 ~2MB 未切换（缺正收益证据）。
2. **单点线性化 + 模型过乐观**：这是本轮没能兑现收益的根因；正确定位是**拒绝门/预筛**，但门需
   基于**更可信的 spill 敏感度**（或外部稳态 A/B）才有意义。
3. **未接** `effectiveBwGbps` 到内核级 roofline（`expectedOps`）——会改 `test_rulers` 量级区间，需先有 end-to-end 证据。
4. **收益不在「选谁」**：与 R47/R47-full-flow 的判断一致——增量在**候选集/内核**，不在把已有候选选得更准；
   L3 定价默认**关**。
