# R59：L3 spill 的实测重标定 + 建模验证（近似建模为何成立）

> 用户决策：做**更可信的 spill 标定**，建模后重跑验证；并解释「非绝对精确建模」为何成功、
> 精确建模差在哪。
>
> 结论先给：发现并修掉一个**标定硬伤**——模型把 L3 容量写成 `3.75 MB`，而本机物理 L3 =
> **8 MiB**（不到一半）→ LRU 模拟系统性**过度逐出**（spill 高估近 2×）。用实测锚点重标定后：
> **模型总分对实测 busy 的误差从 ~18% 降到 ~8%**（yolo），且模型对布局变体的**排序与实测一致**。
> 未改变任何布局选择/数值（三模型 `model_check` 逐位相同）。

---

## 1. 标定硬伤与实测锚点

| 量 | 旧值（R47） | **实测/新值（R59）** | 出处 |
|---|---|---|---|
| L3 容量（LRU） | `3.75e6` | **`8.0e6`**（物理 L3 = 8192K） | `lscpu` / `sysfs index3` |
| 有效容量锚点 | `1.0e6` | **`2.0e6`**（私有 tile 膝点） | R55 §2.3 |
| DRAM 带宽 | 20 GB/s | 20 GB/s（不变） | R55 §2.4 |
| L3 带宽 | 130 GB/s | **145 GB/s**（copy 峰值） | R55 §2.4 |
| `kL3SpillPerByteMs` | `(1/20−1/130)e-9·1e3` | **`(1/20−1/145)e-9·1e3`** | 上式 |

`i5-1135G7` 的 L3 实测：

```
$ lscpu | grep L3            # L3 cache: 8 MiB (1 instance)
$ cat /sys/devices/system/cpu/cpu0/cache/index3/size   # 8192K
```

旧值 `3.75 MB` 来自 R47 的 **copy 足迹膝点**（3→4 MB）——那是**流式访问**的有效容量，
被误当成了 L3 物理容量。**跨算子 LRU 逐出**（模型真正在算的东西）的有效容量应按
**近期重用加权**取到 R55 §3.5 实测的 **~8–12 MB**（≈ 物理 L3）——即 R59 的新值。

实现（`Tuning.hpp/cpp` + `L3Model.hpp`）：新增 `l3PhysicalBytes()/l3PrivateCapBytes()/
l3DefaultCapBytes()/l3DefaultAnchorBytes()/l3DramBwGbps()/l3SramBwGbps()`；`L3ModelConfig`
默认改用它们。`INFVINO_L3_LEGACY=1` 回退旧值做 A/B。

## 2. 建模验证（重跑）

### 2.1 预测 spill（标定 vs legacy）

| 模型 | legacy spill | **calibrated spill** | kernel+reorder（不变） |
|---|---:|---:|---|
| yolov8n-pose | 2.1291 | **1.1357** | 10.2434 |
| yolo11n-pose | 2.4469 | **1.2508** | 11.0017 |
| mobilenetv3-small | 0.2317 | 0.2317 | 1.3884 |

→ 标定把 yolo 的 spill 高估**砍掉近一半**；mb 不变（其占用为 0，spill 与占用无关，R55 §3.5）。

### 2.2 模型总分 vs 实测 busy（credibility）

| 模型 | 实测 busy | legacy 总分（误差） | **calibrated 总分（误差）** |
|---|---:|---:|---:|
| yolov8n-pose | 10.57 | 12.37 (**+17.5%**) | 11.38 (**+7.6%**) |
| yolo11n-pose | 11.39 | 13.45 (**+18.5%**) | 12.25 (**+7.6%**) |
| mobilenetv3-small | 1.379 | 1.620 (+17.5%) | 1.620 (+17.5%) |

→ 标定后 yolo 的模型总分从「高估 ~18%」收敛到「高估 ~8%」。mb 不变（spill 占比小）。

### 2.3 布局变体排序（模型 vs 实测）

三条臂：A=`NO_LAYOUT_MINCUT`（baseline）、B=默认（mincut+分量门）、C=`NO_COMPONENT_GATE`（全量提案）。

| 模型 | 臂 | 实测 busy（×2） | 模型总分 | 排序一致？ |
|---|---|---:|---:|---|
| y8 | A / B / C | 10.51 / 10.50 / 10.59 | 11.3791 / 11.3791 / 11.3791 | 全等（y8 mincut=baseline） |
| y11 | A / B / C | 11.52 / 11.32 / 11.30 | 12.3248 / 12.2525 / 12.2525 | ✅ 模型 A>B=C，实测同 |
| mb | A / B / C | 1.575 / 1.41 / 1.42 | 1.6675 / 1.6201 / 1.6201 | ✅ 模型 A>B=C，实测同 |

→ **模型把布局变体排对了**（符号/次序正确），但**幅度偏小**（y11 模型 −0.6% vs 实测 −1.7%；
mb 模型 −2.8% vs 实测 −10.5%）。

### 2.4 数值回归

三模型 `model_check`：y8 `4.114e-04` / y11 `7.908e-04` / mb `1.215e-02` —— 与 R56–R58
基线**逐位相同**（标定只改**评分**，不改被选中的 kernel/reorder → 布局选择不变）。

## 3. 为什么「非绝对精确建模」成立

### 3.1 决策只需要**符号/次序**，不需要精确 ms

布局门要回答的是「A 布局 vs B 布局，谁更好」——一个**排序**问题。而

```
Cost = Σ_i kernel_ms_i  +  Σ_t reorder_ms_t  +  spill
       └── 实测、逐节点、精确 ──┘  └─ 实测、逐张量、可加 ─┘  └ 唯一非可加项 ┘
```

前两项是**实测的、可加的**，占了总分的 ~90%（y8：10.24 / 11.38）。唯一非可加、需要建模的
`spill` 是**二阶量**（~10%）。因此：

- **结构性不同的变体**（no-mincut vs mincut）的排序由前两项主导 → 模型排对；
- `spill` 的**误差不改变符号**，只让幅度偏小（§2.3）。

### 3.2 逐节点价把非线性「重标定」进可加主问题

min-cut 用 `ρ_i · occ_i` 把全局逐出**线性化**（R55 方案 A）。非线性不消失，而是通过 `ρ_i`
的**重标定**注入；主问题保持可加、可解、零 GPU。这与 TVM meta_schedule 的「Σ 单算子成本 +
学习式修正」同构。

### 3.3 分量门 + 实测门把「模型误差」限制在局部

R58 的分量门只在**离线评分不回归**时接受一个分量；R49 的整网**实测** median 门是最终兜底。
于是模型错也只错在一个分量、且被实测拦——**近似建模的误差被工程化地局部化/兜底**。

## 4. 精确建模差在哪（为什么做不到「绝对精确」）

1. **非可加性（根本）**：L3 逐出是**顺序相关 + 近期重用加权**的。R49 §10 的负结果证明：
   把占用（足迹字节）当 miss 字节线性计入会破坏可加性与量级。精确模型必须对**执行顺序**
   求解——那是 NP-难/需全局模拟，而全局模拟又需要「每节点的工作集」，而工作集取决于
   **正在被决策的 tiling/layout** → **循环依赖**。
2. **有效容量不是常数**：同一硬件上，流式膝点 ~3–4 MB、私有 tile ~2 MB、跨算子 MRU 阈值
   ~8–12 MB（≈ 物理 L3）。精确模型要按**访问模式**选容量，而访问模式又依赖候选。
3. **硬件不用严格 LRU**：流式数据被标记 evict-first，MRU 热点对污染的抵抗力比严格 LRU 强
   ~2×（R55 §3.5）。严格 LRU「精确」模拟会系统性高估逐出——**越"精确"越偏**。
4. **不可观测**：本机无 OA 计数器（R43），**逐节点 spill 无法直接测量** → 「精确」标定是
   **欠定**的；只能拿整网/微基准的一阶差分去拟合。
5. **噪声地板**：整网噪声 ±5%（R42/R46），而布局变体的真实差常常只有 1–3% → 即使模型完美，
   也**无法在该分辨率上被验证**。这决定了「用实测做最终裁决」而非「追求模型精确」。

> 一句话：**精确建模在这里不是「算得不够细」，而是「目标本身欠定 + 循环依赖 + 不可观测 +
> 被噪声淹没」。** 因此正确形态是「可加主问题（实测项精确）+ 非可加项近似求值/定价 +
> 分量局部化 + 实测兜底」——即本项目的路线。

## 5. 复现

```bash
# 标定锚点单测
./build/test_rulers        # R59 段：物理 L3=8MB、锚点 2MB、legacy 回退

# 预测 spill / 模型总分（calibrated vs legacy）
INFVINO_LAYOUT_REPORT=1 ./build/kernel_run --plan models/yolov8n-pose/model.plan --report --iters 12
INFVINO_L3_LEGACY=1 INFVINO_LAYOUT_REPORT=1 ./build/kernel_run --plan models/yolov8n-pose/model.plan --report --iters 12

# 变体排序验证（A=no-mincut / B=default / C=no-component-gate）
INFVINO_NO_LAYOUT_MINCUT=1 INFVINO_LAYOUT_REPORT=1 ./build/kernel_run --plan models/yolo11n-pose/model.plan --report --iters 12

# 数值回归
python3 scripts/model_check.py --model yolov8n-pose --repo "$PWD"
```

## 6. 下一步（可选）

- 标定值目前只改了**评分**（选择不变）。要让标定**改变选择**并带来整网收益，需要：
  (a) 把 `effectiveBwGbps`（并发维 `BWmax(C)`）接进逐节点内存 roofline（R55 §6.1，未接）；
  (b) 把 `spill` 的幅度偏差用**受控微基准**（真实 conv/gemm tile 形态的 `l3pollute`）复标，
      让模型从「排对序」升级到「量级也对」。
- 两者都需整网稳态 A/B 验收，且都**不应**退化成「Σ 足迹 > 常数」的硬阈值（R55 §3.5）。
